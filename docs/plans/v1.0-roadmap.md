# Utterform 1.0 — roadmap

Planned with Jonas on 2026-11-07. This replaces the three-stage "Road to 1.0" of
2026-10-31 in [DEVELOPMENT.md](../DEVELOPMENT.md). After 1.0, versions continue normally.

No preview, no tag, no release until 1.0 (Jonas, 2026-11-07): he tests everything together
at 1.0, which is the next release. 0.8.0 was the last one. One stage per session.

## How a stage session runs

Jonas starts a stage with one line: *"Lies `~/git/utterform/docs/plans/v1.0-roadmap.md`
und mach die nächste offene Etappe."* Everything else is here.

1. **Pick.** `git fetch`; the next stage in the table below whose status is neither
   "merged", "released" nor "in progress" is yours. Two sessions may run in parallel.
2. **Claim.** Own worktree and branch from current `origin/main`
   (`git worktree add ~/git/utterform-<topic> -b work/utterform-<version>-<topic> origin/main`;
   never work in `~/git/utterform` itself, another session may use it). First commit: set the
   stage's row to "in progress", push it at once so the other session sees it.
3. **Ask before building** what only Jonas can decide: every **Proposal** of the stage, and
   anything marked "discuss first". One question at a time, as a situation with a recommendation,
   in German. Do not build on an unconfirmed proposal.
4. **Style samples for anything visible.** Before building UI, show Jonas a quick mock-up as an
   image (send it with `SendUserFile`, he decides on the phone). Not long polishing.
5. **Build with checks.** Tests for the new behaviour, `npm run check`, `npm test`,
   `npm run build`, `npx playwright test`, Rust checks when Rust changed
   (`cargo fmt --check`, `cargo clippy -D warnings`, `dbus-run-session -- cargo test`),
   diagnostics per DEVELOPMENT.md. Docs in the same PR: CHANGELOG entry
   `## <version> · <title> (on main, ships with 1.0)`, `docs/releases/v<version>.md`,
   README/ARCHITECTURE/TESTING where behaviour changed, the stage's row and a short handoff in
   DEVELOPMENT.md. App version, installers and README release links stay at 0.8.0.
6. **Merge at once.** PR, CI green, merge with a merge commit. No preview build, no tag, no
   release. Set the row to "merged, ships with 1.0".
7. **Report and hand on.** Tell Jonas in three sentences what is now in `main`, update the Mioru
   note `software-projekte/Utterform/README.md` and memory, remove the worktree, and give him the
   one line above for the next stage.

1.0 itself ends differently: version bump everywhere, then Jonas tests the installed app on
Linux, Windows and macOS, and only then tag and release (see its section).

## Idea

Learn from Superwhisper (superwhisper.com, integrated into Omarchy 4.5) without copying it,
and without its subscription:

- **Transcription stays GPT Transcribe with the user's own OpenAI key.** It is very strong
  for German and costs almost nothing. Local Whisper stays as the offline option.
- **Everything that needs a text model can optionally use the user's ChatGPT subscription
  through the Codex login**, so text actions and context cost nothing extra.

**Proposal (order):** the Omarchy backend first because it is small and the CLI already
exists; Settings next so every later feature gets a fixed place; Codex before context
because context is mainly a text-model feature; the assistant last because only then is
known what it has to ask.

### 0.8.0 — Omarchy dictation backend

Omarchy 4.5 has a dictation layer: Setup → Defaults → Dictation chooses a backend
(Superwhisper, Voxtype). Omarchy then binds **Alt+Space** to toggle and **holding Right Alt**
to push-to-talk, and calls `omarchy-dictation-<backend> start|stop|toggle`.

- Ship two scripts with the Linux install when Omarchy is present:
  `omarchy-dictation-utterform` (`start` → `utterform --start`, `stop` → `utterform --stop`,
  `toggle` → `utterform --toggle`) and `omarchy-install-dictation-utterform`
  (`omarchy-dictation-use utterform`, then reload Hyprland). They go to `~/.local/bin`,
  which is on the PATH, so `omarchy default dictation utterform` finds them.
- Omarchy binds the keys only when a command named like the backend exists (`utterform`);
  the installer's launcher already provides it.
- Menu row: Omarchy's own menu lists only Superwhisper and Voxtype, but users can extend it
  in `~/.config/omarchy/extensions/omarchy-menu.jsonc` by reusing the id
  `setup.default.dictation.utterform`. The installer adds that row without touching the
  user's other entries (JSONC with comments — edit carefully, back up first).
- Check: `--stop` while idle and `--start` while recording must be harmless (push-to-talk
  sends both rapidly); stop must arrive even if the start cue is still playing.
- Uninstall removes scripts and menu row and, if Utterform was the backend, clears it.
- Open: offer an upstream pull request to Omarchy later? Not before 1.0.

Acceptance: on `asus16`, choose Utterform in the menu, Alt+Space dictates, holding Right Alt
dictates while held, Super+D keeps working.

### 0.9.0 — Settings from scratch

Rules from the decisions above. Design contract:

- No Save/Cancel. Each control writes at once (debounced for text fields), invalid input is
  shown at the field and not written.
- Minimal text: labels of one or two words, no explanations in the window (a tooltip at
  most). Technical details (model id, effort, prompt text) one level deeper, never in front.
- Everything findable: **Proposal:** a search field at the top that filters rows across all
  categories.
- **Proposal (categories):** Recording (microphone, shortcut, sounds) · Transcription
  (cloud/local, language, vocabulary) · AI (provider OpenAI key / Codex, model, actions) ·
  Context (selection, clipboard, per-application rules) · Output (cursor, clipboard, file) ·
  App (autostart, history, diagnostics, Omarchy). Later stages fill AI and Context; until
  then those categories show only what exists.
- Reuse from 0.7.14 what worked technically (vocabulary word by word, local model chosen in
  the list); not its layout.
- Show Jonas one quick mock-up before building, as an image (he decides on the phone).

### 0.10.0 — Codex login for text actions

- New text provider next to the OpenAI key: **ChatGPT subscription (Codex login)**.
  Transcription is not affected.
- Jonas's `kit` (jli-software/kit, Rust) already does this: it reads the Codex CLI login
  from `~/.codex/auth.json` and calls the Responses API at `chatgpt.com/backend-api/codex`.
  Reuse that approach; verify token refresh and expiry behaviour before relying on it.
- Marked "experimental" in the interface (confirmed). OpenAI does not officially support
  third-party apps using the subscription and may block it; Utterform is public.
  **No fallback** to the OpenAI key (Jonas, 2026-11-07): a failure is shown as such.
- Model list from `~/.codex/models_cache.json` (as in kit); default the smallest fast model.
- Measure latency against the API path; dictation must stay quick.
- Requires the Codex CLI installed and logged in; Settings says so in one line with a link.

### 0.11.0 — Context: selected text and clipboard

The core feature. Spoken text becomes an instruction, the selected text the material:
select an email, say "reply that I have time on Monday", get the reply at the cursor.

- Sources, each switchable: selected text, clipboard. Never logged (privacy rules in
  ARCHITECTURE.md → Diagnostics apply), capped in length.
- Linux: read the primary selection directly (`wl-paste --primary`, X11 `xclip -o -selection
  primary`) — no simulated copy.
- Windows/macOS: clipboard only for now (decided 2026-11-07). A simulated Ctrl+C / Cmd+C
  would interrupt a terminal; UI Automation / Accessibility remain an option after 1.0.
- Which actions use context: a new built-in action **"Context"** only (decided 2026-11-07);
  plain dictation and the other actions never read context.
- Delivery replaces the selection where the application allows it.

### 0.12.0 — Action per application (decided 2026-11-08, built)

Example: email action in the mail client, plain text in the terminal. Utterform already
knows the active window class on Linux (`typing/linux.rs`).

- **Proposal:** off by default; a short list "application → action" in Settings → Context;
  the chosen action is shown (tray tooltip or notification) so it never surprises.
- To discuss with Jonas before building: is it worth it, and how to avoid surprise.

### 0.13.0 — Audio files

Transcribe a voice message or recording: drag onto the window, an Open button,
`utterform --file <path>`, and "Open with" from the file manager. Result goes to history and
clipboard; text actions apply as usual.

- Cloud: upload the file to GPT Transcribe; respect the API's size limit (split or compress
  longer files). Check which formats the API accepts (WhatsApp `.opus`/`.ogg`).
- Local: decode to 16 kHz mono for Whisper; check Opus support of the decoder used.

### 0.14.0 — First-run assistant (decided 2026-11-08, built)

The contract on Draft PR #39 (`docs/plans/v0.8.0-onboarding-assistant.md`) stays the base,
adapted to the new Settings and the Codex choice: skippable, short welcome, OpenAI key or
local model, optional Codex login, language by typing `de`, vocabulary optional.
