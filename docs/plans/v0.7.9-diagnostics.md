The released tree already has a small native logger in `src-tauri/src/diagnostics.rs`. It writes
timestamped lines to stderr and one `utterform.log` beside local app data, deletes that file after
it exceeds 1 MiB, and opens it for every line. Call sites cover cues, microphone opening/arming,
some typing decisions, local Whisper features and numbered Live sessions. `commands.rs` exposes
only the path. `App.svelte` reads it at startup and shows the literal path under Recording →
Recording feedback. There are no levels, retained rotation, general command-error boundary,
panic hook, unhandled WebView error bridge, unexpected-exit marker or clickable support action.

The current Tauri stack is 2.11.x. As verified while preparing this handoff, the compatible stable
plugins are `tauri-plugin-log` 2.7.0 and `tauri-plugin-opener` 2.5.5; do not select the available
3.0.0 alpha crates. The log plugin supports OS log directories, levels, custom formatting, a
maximum file size and `RotationStrategy::KeepSome`. The opener plugin supports native open and
reveal operations on Linux, Windows and macOS. Use their Rust APIs behind no-argument Utterform
commands; do not expose arbitrary user-supplied paths or broad JavaScript opener permissions.

## Product contract

Deliver comprehensive, local and resource-bounded diagnostics for the full application flow:

1. Logs stay on the device until the user explicitly copies them or opens their location. There
   is no telemetry, analytics, automatic upload, remote crash reporting or network destination.
2. Normal production logging records lifecycle boundaries, outcomes, failures, fallbacks and
   durations at `INFO`, `WARN` or `ERROR`; it does not record continuous state or user content.
3. Keep the active log and the two most recent rotated logs at no more than 2 MiB each. The normal
   disk budget is therefore about 6 MiB. Never use `KeepAll`.
4. Settings → General ends with a **Support & diagnostics** group containing:
   - **Copy diagnostics** — puts an agent-readable, bounded report on the clipboard;
   - **Open log file** — opens the current file in the system's default application;
   - **Open log folder** — reveals the current file in Finder/Explorer/the Linux file manager;
   - the actual current log path and short text stating that logs are local and contain no
     transcript or audio.
5. Support actions are immediate operations, like model/API-key/history resource actions. Save
   and Cancel neither apply nor undo them, and a failed action stays visible in that group.
6. Errors shown to the user carry a short correlation reference when they represent an actual
   backend or unexpected frontend failure. That reference must locate the matching log event.
   Expected validation guidance such as choosing an output or adding a key is not an error event.
7. A Rust panic, an unhandled JavaScript error/rejection, or a previous run that did not reach a
   clean Tauri exit leaves useful evidence. A segmentation fault, killed process or native driver
   crash can only be identified as an unclean exit; collecting platform crash dumps is a future,
   separately approved feature.

## Resource and privacy budgets

### Resource rules

- Configure the release logger at `INFO`; use `DEBUG` only for debug builds. Dependency noise must
  not be written. Accept only Utterform-owned Rust targets and the dedicated sanitized frontend
  bridge target.
- Write one record at meaningful boundaries. Never log audio samples/callbacks, RMS levels,
  transcription deltas, cursor chunks, animation frames, status polling successes or retry-loop
  iterations individually. Aggregate counts and elapsed time after the work leaves the hot path.
- Preserve the existing `MAX_LOGGED_EVENTS` bound for Linux Live focus diagnostics and add an
  equivalent bound/rate limit to every new repeated source.
- A log failure is best-effort and must never fail recording, transcription, history or output.
- **Copy diagnostics** is explicit and may read files, but its final clipboard text is capped at
  256 KiB. Read only the newest tails needed to meet that cap; include a clear truncation marker.
  Do not read settings, history, recordings, exported documents or the clipboard's old contents.

### Privacy allowlist

Allowed diagnostic metadata includes app version, OS/architecture, desktop/session backend,
event/correlation/session ids, durations, counts, enabled modes, model/action identifiers, HTTP
status, microphone/output device name, process/application name, window class/bundle identifier
and sanitized error category. Those device/application identifiers are required to diagnose the
audio and cursor-delivery failures for which the existing log was introduced.

Never log or copy:

- OpenAI keys, Authorization values, credentials, tokens or keyring payloads;
- transcript, history, clipboard, output-file or audio contents;
- custom prompts, prompt overrides, vocabulary, language terms or recording context;
- request/response bodies, WebSocket deltas or raw third-party error bodies;
- window titles, typed text, user names, raw home-directory prefixes, complete user-selected paths;
- full settings/history JSON.

Normalize every record to one physical line, strip control characters, redact the home directory
to `$HOME`, and represent a user-selected path by purpose plus basename only when the basename is
needed. Apply that sanitizer again while assembling a copied report, including legacy lines.
Preserve the current privacy-safe Linux focus event rendering: no titles, classes or workspace
names. Add explicit negative tests with canary secrets and transcript text at the workflow/log
sink boundary; a generic string sanitizer cannot infer that arbitrary prose is a transcript, so
the primary protection is never passing user content into diagnostics.

## Implementation order

### 1. Dependencies and logger bootstrap

Update `src-tauri/Cargo.toml` and `src-tauri/Cargo.lock` with stable Tauri-2-compatible versions of
`log`, `tauri-plugin-log` and `tauri-plugin-opener`. Do not add JavaScript plugin packages unless
the verified Rust API cannot fulfill a required operation; the intended design needs none.

In `src-tauri/src/lib.rs`, register a `tauri_plugin_log::Builder` before application setup and the
opener plugin with the other plugins. Configure:

- `TargetKind::LogDir` with an explicit Utterform file stem;
- stderr as the development/terminal target;
- `max_file_size(2 * 1024 * 1024)`;
- `RotationStrategy::KeepSome(2)`;
- release `LevelFilter::Info`, debug-build `LevelFilter::Debug`;
- a filter that rejects non-Utterform dependency targets;
- an ISO-8601 UTC format containing timestamp, level, Rust/frontend target and message.

The backend is the source of truth for the resolved directory and filename. Use Tauri's log-path
resolver/the plugin's actual configured result; never reconstruct platform paths in Svelte. The
expected standard roots are `$XDG_DATA_HOME/software.jli.utterform/logs` on Linux,
`~/Library/Logs/software.jli.utterform` on macOS and
`%LOCALAPPDATA%\\software.jli.utterform\\logs` on Windows, but platform verification must confirm
the exact resolved path and name.

Do not delete or move the legacy app-local-data `utterform.log` during upgrade. It is at most 1
MiB and may contain the evidence that led to the update. The new support report may include its
bounded tail under a `legacy log` heading when it exists.

### 2. Turn `diagnostics.rs` into the single diagnostic boundary

Keep the module rather than scattering plugin details. Replace its direct file writer with:

- stable `info`, `warn` and `error` event helpers;
- monotonically allocated process-local operation/recording ids;
- a one-line field formatter and centralized redaction helpers;
- resolved current/rotated/legacy log discovery;
- a bounded diagnostic-report builder;
- clean/unclean-run marker handling;
- panic-hook installation that chains the previous hook.

Use stable dotted event names such as `app.started`, `recording.started`,
`transcription.failed` and `delivery.completed`. Fields are `key=value`; quote/escape whitespace
consistently. Do not serialize arbitrary domain structs or error debug dumps. The report header
contains format version, generated UTC time, Utterform version, OS, architecture, session id and
whether the previous run was clean, followed by log tails oldest-to-newest.

At setup, inspect a minimal marker in app-local-data. An existing marker means the previous run
was unclean; log that fact, then atomically replace it with this run's id. On `RunEvent::Exit`, log
`app.exiting` and remove the marker. Tray Quit must still cancel active audio before `app.exit(0)`.
Power loss and force-kill may therefore be reported as unclean, which is intentional. Marker
failure is logged best-effort and never prevents startup.

Install the panic hook only after the logger is available. Log the sanitized panic payload,
source location, thread name and a backtrace captured only on panic, then invoke the prior hook.
The hook must avoid recursion and must not claim to catch aborts or native faults.

### 3. Correlate the native workflow

Add one diagnostic session id per batch or Live recording and carry it through the existing
native ownership path (`StartedRecording`, `ActiveRecording`, `RecordingArtifact`, Live `Session`)
without exposing it as user data. Do not replace `Instant` where it is required for identity or
timing; the diagnostic id is separate.

Instrument these boundaries without logging payloads:

- app startup/setup completion/failure, startup intent, second-instance intent, reveal/hide,
  tray quit and clean exit;
- hotkey installation/apply failures and autostart read/write failures;
- recording requested/opened/armed/paused/resumed/stopped/cancelled/limited, elapsed audio,
  device/configuration metadata, aggregated glitches and writer/stream failures;
- Live setup/connect/stream/input shutdown and the already bounded focus classifications;
- batch/Live transcription start/completion/failure with engine/model, audio duration, elapsed
  time, request error class and HTTP status — never request/response text;
- transform start/completion/fallback/failure with action id, model/effort and elapsed time —
  never transcript, instructions or generated text;
- history attempt, clipboard/file/cursor delivery outcomes, warning categories and total
  completion. File diagnostics may include format and basename, not the directory or contents;
- settings save, key presence/update/delete and model download/delete outcomes without values,
  secrets or full settings;
- meaningful failures currently discarded with `let _ = ...` or plain `eprintln!`, including
  window hide/reveal, event emission, notification, tray fallback and setup cleanup failures;
- cue and local-model details already present, converted to stable levels/events.

Do not add success records to `get_recording_status`, `get_live_status`, support queries or other
polling. Log their errors at the point that owns the failure. Ensure every `Result` that reaches a
user as an actual operational failure has one owning error event; avoid duplicate copies in
multiple layers.

The logging work must not alter existing behavior. In particular:

- audio callback errors remain latched and are logged after leaving the real-time callback;
- a transformation failure may still fall back to the plain transcript;
- history remains attempted before external delivery, preserving text before clipboard/file/
  typing failures;
- `finish_recording` still answers only after requested outputs complete, while the Done cue is
  detached and never delays the next recording;
- cancel and tray Quit still discard recordings; diagnostics never retain audio.

### 4. Capture frontend-only failures

In `src/lib/api.ts`, add typed no-arbitrary-path commands for diagnostic information, copy, open
file, open folder and frontend error reporting. In `App.svelte`, register and clean up global
`error` and `unhandledrejection` listeners. Send only a source category, sanitized message, stack
with home/source paths reduced, and the current UI phase; never serialize rejection objects or
application state. Swallow logging-command failure so logging cannot create a rejection loop.

Backend command failures are logged by their native owner. Report frontend-only plugin failures
(for example autostart calls), unexpected state-machine exceptions and global errors explicitly.
Do not duplicate expected validation messages or every caught native command rejection.

### 5. Add the Settings support surface

Move the literal log-path presentation out of Recording feedback. Add **Support & diagnostics** as
the final group in General. The existing sound test remains in Recording. The new group uses the
backend-returned path and has keyboard-accessible buttons:

- **Copy diagnostics** calls one native command that builds the bounded report and writes it with
  the already-installed clipboard plugin. Show `Diagnostics copied` plus the copied byte/line
  count; this explicit action may replace the clipboard.
- **Open log file** opens only the backend-owned current file through the opener Rust API.
- **Open log folder** reveals that same file (or opens its parent if reveal is unavailable on the
  platform), again with no path argument from the WebView.

Disable only the action currently in flight. Surface a concise failure in this group and preserve
the visible path for manual recovery. The controls must remain reachable at 360 × 400, under
keyboard navigation, in light/dark themes and with reduced motion. They are independent of the
settings draft and do not close the dialog.

### 6. Documentation and durable development gate

Update `README.md` privacy/support sections and `docs/ARCHITECTURE.md` to describe the new path,
rotation, event/correlation model, explicit clipboard action and privacy contract. Update
`docs/TESTING.md` with exact automated and manual evidence. Keep the generic invariant in
`docs/DEVELOPMENT.md` and the pull-request checklist added by the planning PR; refine them only
when the implementation proves a statement inaccurate, never remove the requirement.

Do **not** bump version files, create `docs/releases/v0.7.9.md`, update the changelog or perform
release work in the Claude Code handoff. ADA does those after review and acceptance of the diff.

## Definition of done

- A normal or failing Record → Transcribe → Transform → Deliver run can be reconstructed by
  ordered, correlated events without any user text or secret.
- Current plus two rotated files stay within the configured approximately 6 MiB budget; repeated
  events and clipboard reports are independently bounded.
- Rust panics, frontend unhandled errors and previous unclean exit are represented honestly; the
  app makes no unsupported native-crash-dump claim.
- Copy/Open actions work from General on Linux, Windows and macOS without accepting a path from the
  WebView, changing settings, blocking recording or sending network traffic.
- Documentation and the PR template require future features to include privacy-safe diagnostic
  coverage and resource bounds.
- All relevant automated checks and explicitly claimed native/manual checks pass on the exact
  reviewed commit. No release, deployment or automatic upload occurs as part of implementation.
