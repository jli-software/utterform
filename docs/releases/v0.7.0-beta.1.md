# Utterform 0.7.0 beta 1 — macOS asks for the microphone and types at the cursor

The first release meant to be used on a Mac. Until now the macOS build started,
but never asked for the microphone and could not type: 0.6.1 on a MacBook Air
(M2, macOS 26) showed no permission dialog and no entry under System Settings.
**GPT Transcribe, Local Whisper, the dictation key and typing at the cursor are
now expected to work on Apple Silicon; Live Dictation on macOS remains deferred.**
Linux and Windows are unchanged.

## What was wrong

- **The app was signed without the microphone entitlement.** Every macOS build is
  signed with the hardened runtime. Under it, macOS grants a process the microphone
  only when its code signature carries `com.apple.security.device.audio-input`; the
  usage description in Info.plist alone is not enough. Utterform had the description
  and not the entitlement, so TCC denied the microphone silently: no dialog, no
  switch to turn on, a recording of silence.
- **Typing at the cursor did not exist on macOS.** The output reported "not available
  on this platform yet".
- **A hidden window could not be brought back from the Dock.** Closing the window
  hides it to the tray; a click on the Dock icon did nothing.

## What changed

- **The bundle carries the audio-input entitlement** (`src-tauri/Entitlements.plist`),
  and the packaging step refuses an app signed without it or without the usage
  description. The first recording makes macOS ask for the microphone. A
  microphone the user has denied is reported before recording, with the path to
  the switch, instead of producing an empty transcript.
- **Typing at the cursor on macOS.** Paste sends ⌘V, which every Mac window takes,
  terminals included. Keystrokes post one character per keyboard event, as
  Unicode, so the keyboard layout does not matter, with the same adjustable delay
  as Linux. Both need **Accessibility**: the first delivery opens the system's
  request dialog, Settings → Typing at the cursor says so beforehand, and a refused
  delivery is a warning next to a clipboard that already holds the text.
- **A Dock click reveals the window** after it was closed to the tray.
- **The dictation key** is unchanged: `Ctrl+Alt+D` is ⌃⌥D on a Mac. `Cmd` or `Super`
  in Settings means ⌘. The reserved key needs no permission.

## Please verify on a real Mac

Install the DMG, open it once with *Open Anyway* (the bundle is ad-hoc signed, not
notarized), then:

1. Start a recording. Expected: the macOS microphone dialog, once. Deny it once on
   purpose, record again, and read the message; turn it on under Privacy & Security
   → Microphone.
2. GPT Transcribe and Local Whisper with clipboard output.
3. Enable **Type**, record into TextEdit. Expected: the Accessibility request dialog,
   a warning in Utterform, the text on the clipboard. Turn Utterform on under
   Accessibility, record again: the text is pasted. Then Settings → Keystrokes, once
   more, including a line break and an umlaut.
4. ⌃⌥D from another window; change it to ⌘⇧D in Settings.
5. Close the window, click the Dock icon.

Send the log (`~/Library/Application Support/software.jli.utterform/utterform.log`,
path shown in Settings). **Every update of an ad-hoc signed app starts the
Accessibility and microphone grants over**, because macOS ties them to the hash of
that exact build; remove the old entry and add the new one. A Developer ID
signature would keep them across versions — see `docs/MACOS.md`.
