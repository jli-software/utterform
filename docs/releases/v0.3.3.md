# Utterform 0.3.3 — The tray icon answers a click on Linux

## Correction to 0.3.2

0.3.2 stated that tray clicks cannot be delivered on Linux. That was wrong. It is true of libayatana-appindicator, which Tauri's tray uses and which exposes `SecondaryActivate` but no `Activate` — but not of Linux. Chromium-based applications serve the StatusNotifierItem themselves and therefore do receive left clicks, which is why other tray icons open their window on a single click.

Utterform now does the same.

## Improvements

- A left click on the tray icon opens Utterform on Linux, including Omarchy/Hyprland with Waybar. A middle click does the same. The menu with **Show Utterform** and **Quit** remains on right click.
- Utterform serves its own StatusNotifierItem on Linux instead of going through AppIndicator. It re-registers itself when the panel restarts, so a Waybar restart no longer loses the tray icon.
- If no StatusNotifierItem host answers, Utterform falls back to the previous AppIndicator tray, which shows the menu but reports no clicks.
- The tray icon is handed over as pixel data rather than a temporary file.

## Verification

A test registers a StatusNotifierWatcher on a private session bus, lets the real tray register with it, and calls `Activate` — the same D-Bus call a left click produces. The window-opening action must run exactly once. This runs on Linux in CI through `dbus-run-session`.

What automated tests cannot show is the behaviour of a specific panel. Whether your Waybar sends `Activate` on left click needs one click on Omarchy.
