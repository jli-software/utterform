# Utterform 0.4.0 — Dictate from anywhere

## A global dictation hotkey

Utterform no longer has to be the focused window. Bind it in `~/.config/hypr/hyprland.conf`:

```
bind = SUPER, D, exec, utterform --toggle
```

Press it once to start recording, again to finish. The window stays where it is — you keep working in the application you are dictating into. `--start`, `--stop` and `--cancel` are available for separate bindings, and plain `utterform` still shows the window. If Utterform is not running, the command starts it and records anyway.

This deliberately uses the compositor's own binding rather than an in-application shortcut. Wayland gives no application the right to grab a global key, so anything else would be a workaround that breaks. The single-instance behaviour from 0.3.2 carries the command to the running app.

## Typing at the cursor

**Type** joins Clipboard and File in the output bar, shortcut `T`. The finished text is typed into whatever window has focus, so dictation ends where you were already working instead of in a paste buffer.

This needs the session's typing tool — `wtype` on Wayland/Hyprland, `xdotool` on X11 — because a Wayland client cannot synthesize input for another window:

```bash
sudo pacman -S --needed wtype
```

The three outputs are independent and typing runs last, once the clipboard and file are already written. A missing tool produces a warning that names the package to install; it never costs you the text.

## Verified

41 native tests and 31 interface tests, including: every combination of the three output targets against every combination of successes and failures; the hotkey starting and finishing a recording through the event the backend emits; a hotkey that had to start the app first; and stop/cancel being ignored when nothing is recording. `wtype` and `xdotool` both receive the text on stdin, so a transcript starting with `-` or containing newlines is never read as options — asserted in a test.

Fixed on the way: a component torn down while still starting up could leave a keyboard handler bound to the window. Listeners are now bound before the first await.

Not verified here: an actual keypress on Omarchy, and actual typing into another window. Both need a real desktop session.
