# Utterform 0.7.3 — Local Whisper runs on your processor, not on the build server's

Choosing Local Whisper and starting a transcription closed Utterform instantly on
Linux. The recording was not lost on the way — the application was stopped by the
operating system before a single sample was read. GPT Transcribe was never affected,
because it never touches the local engine.

This release fixes the cause. Nothing else changes: the shortcut recorder and the
startup switch from 0.7.2 are unchanged.

## What was wrong

whisper.cpp is compiled from source when Utterform is built, and by default it builds
for **the machine doing the compiling**. Our release binaries are built by GitHub's
servers, whose processors have AVX-512 and AMX — instruction sets a laptop or mini PC
generally does not have. Every one of those instructions was baked into the binary.

On a processor without them, the very first one is fatal: the system stops the process
with *illegal instruction*. It happened while the Whisper model was being loaded, in
ordinary bookkeeping code — before whisper.cpp's own check for which processor it is
running on could pick a suitable routine, which is why that check did not help.

Confirmed on an Intel Core i3-N300 (AVX2 yes, AVX-512 no): three crashes in two
minutes, identical every time. It was **not introduced in 0.7.2** — the build has
worked this way since the first release. Whether it actually crashed depended on which
processor the build server happened to have that day and on which processor you ran
it, which is why it went unnoticed for so long.

## What changed

- **The build now targets every supported desktop instead of the build machine.**
  On Intel and AMD that means SSE4.2, AVX, AVX2, FMA, F16C and BMI2 — the set any
  desktop processor of the last decade has — and deliberately not AVX-512, VNNI or
  AMX. On Apple Silicon it targets the M1, the oldest Mac Utterform supports.
- **Speed is essentially unchanged.** Whisper's quantized arithmetic gains little from
  AVX-512, and AMX only matters on server processors.
- **Windows was exposed to exactly the same fault** and is fixed with it. Nobody had
  reported it there, because Local Whisper had not been tried on Windows.
- **Two checks now stand in the way of a repeat.** The packaged Linux binary is
  examined for those instructions before release, and a test refuses a build of
  whisper.cpp that carries them on any platform.
- **The log names the instruction set** the first time a local transcription runs, so
  a future report of this kind can be identified from one line.

## If you had the crash

Install 0.7.3 and try Local Whisper again — no settings, downloaded models or history
are affected. Your recordings were never at risk: the crash happened before the audio
was read.
