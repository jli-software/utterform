# Utterform 0.4.6 — A window running as administrator is named, not typed into

Jonas found why 0.4.5 still did not paste into his Windows Terminal: it runs as administrator. Windows lets a program inject input only into windows of its own integrity level or below, so an ordinary Utterform cannot type into an elevated terminal, whatever chord it presses. That is a Windows rule, not something Utterform can get around — only a code-signed program with the `uiAccess` privilege may, and Utterform's Windows builds are unsigned.

What Utterform can do is say so. `SendInput` reports the dropped keystrokes as delivered, so 0.4.5 pasted into the elevated terminal, was told it had succeeded, and nothing arrived. Utterform now reads the focused window's integrity level first and, when it outranks Utterform's own, delivers a warning instead of a paste that goes nowhere:

> WindowsTerminal is running as administrator, and Windows lets no ordinary program type into it. Paste from the clipboard, or start Utterform as administrator too.

The text is on the clipboard either way. To have it typed into an elevated terminal, start Utterform as administrator as well — an elevated program may type into any window — or run the terminal without elevation and elevate only the commands that need it (`sudo` on Windows 11, or gsudo).

## Also in the log

Jonas's 0.4.5 log shows the start click playing to the end on every recording, on a Jabra headset, with a webcam microphone. Whether those recordings were started with the window in the background, where 0.4.4 stayed silent, is the open question for the start-click story; nothing changes here until it is answered.
