# Utterform 0.4.5 — Paste into a Windows terminal, cues on their own threads, and a log

Jonas's second afternoon on Windows with 0.4.4: the text pasted everywhere except into a terminal, the start click was still silent unless Utterform's own window was in front, and the tray dot was louder than it needed to be. This release fixes the first, changes what can be changed about the second without a Windows machine at hand and adds the means to settle it, and tones down the third.

## Typing at the cursor reaches Windows Terminal

Utterform pressed Ctrl+V as a virtual key with no scan code. Every classic window takes that; Windows Terminal does not — it asks for the left and right Control keys separately and reads the scan code off the message, and a synthesized key that carries neither looks like no key at all. Every key is now sent the way the keyboard sends it, with the left-hand modifier and its scan code.

On top of that, a terminal window now gets the paste every Windows console understands, **Shift+Insert**, rather than the shell's Ctrl+V: Windows Terminal, the classic console host behind `cmd` and PowerShell, mintty and Git Bash, PuTTY, ConEmu and Cmder, Alacritty, WezTerm, Hyper and Tabby are recognised by their window class or the program behind it. Every other window keeps Ctrl+V, so a browser or an editor does not get a chord that means something else there.

Windows Terminal warns before pasting text with more than one line unless that warning is switched off in its settings. A transcript with paragraphs will show that dialog once; the text is on the clipboard either way.

## The start click on Windows

Jonas's observation on 0.4.4: the start click sounds when Utterform's window is in the foreground and not when it is behind another window, the stop click almost always sounds, and once even the stop click was missing. Two things about the start cue were different from the stop cue that works, and both are gone:

- **Every cue now plays on a thread of its own.** The start cue used to be opened on the thread answering the interface — on Windows the main thread, the one WebView2 owns — and closed on another. Opening the microphone ran on that thread too, stalling the window for as long as the device took. Starting a recording no longer touches the main thread at all.
- **The start cue is opened after the microphone, not before.** Opening a capture stream can reconfigure the device that plays the cue — a headset switching to its hands-free profile, a dock re-plumbing a shared codec — and a cue started a moment earlier would be cut off while every sample still counted as taken. Capture still discards until the cue has been heard, so the click can never land in its own recording.

Whether that is the whole answer will be known from the log, which is new.

## A log, and a way to test the sounds with the window in the background

A Windows release build has no console, so until now nothing Utterform said about a silent cue reached anyone. Every cue now writes a line to `utterform.log` in the app's local data directory — which device, how long the stream took to open, how long until the device had taken the whole cue, or why it could not be played — and so do the microphone opening, the recording arming and the paste decision. Settings → Voice → Recording feedback shows the path.

Next to it is **Play the sounds in 5 seconds**: click, switch to another window, and the three cues play the way a hotkey recording plays them, without a microphone involved. What each sound did is shown afterwards and written to the log. If the sounds play there and the start click of a real recording still does not, the microphone is what silences it; if they do not, the cue path is.

## A smaller dot on the tray

The recording dot is a third of its 0.4.4 size and has no white ring around it: a recording light in the corner of the icon rather than a badge over it. Still six pixels across at the 16 pixels a Windows tray gives it. Windows 11 still hides new tray icons behind the overflow arrow until the icon is pinned.

## Upgrading

Nothing to configure. The log file appears on first start; it starts over once it reaches a megabyte.

## Downloads

See the [0.4.5 release](https://github.com/jli-software/utterform/releases/tag/v0.4.5). Windows builds are unsigned; macOS bundles are ad-hoc signed and not notarized. Verify assets against `SHA256SUMS.txt`.
